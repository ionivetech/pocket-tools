# PR verdict — pockettools-phase4-mvp-tools

**Title:** `feat(tools): Phase 4 — 16 MVP tools, uniform tool UI, dialog focus fix`

**Branch:** `feature/phase-4-mvp-tools` (base `fc449ea`, 32 commits)

## Summary

Delivers Phase 4 of PocketTools: 16 tools on the shared four-rail tool pattern
(pure logic → schema → PrimeVue component → unit tests), a dialog initial-focus
fix, and a 20-tool catalog. No new runtime dependency. No user data leaves the
browser.

An independent review and security pass ran after the first green gate and found
nine defects, all fixed here with regression tests. The most important thing to
know when reading this diff: **two of my earlier claims about the QR encoder were
wrong and are retracted** — see "Retracted claims" below.

## What changed

- **14 new tools + 2 placeholders finished.** Data/dev: JWT decoder, hash
  generator, regex tester, diff checker, cron helper, cURL→fetch converter. Text:
  markdown preview, table-to-markdown, case converter. Everyday: password
  generator, unit converter, color picker, date/time helper. Media: QR generator,
  image compressor, image resizer.
- **Dialog initial focus (A1).** Opening the palette, the shortcut help, or a
  tool's options drawer focuses the primary control instead of PrimeVue's close
  button, keeping the visible ring, the focus trap, Esc, and invoker restore.
- **Uniform tool UI (A3).** Every tool view is `ToolDualPane` → toolbar / input /
  output / footer, `pt-option-group` fieldsets, one status line, `ToolActions`,
  real empty/error/success states, 44px targets, everyday-language copy.
- **Regex matching moved off the main thread.** A worker the UI can terminate
  after 2s, shared across runs.
- **The QR encoder ships level M only.** See below.

Root causes, not symptoms, for each finding:

- **Markdown freeze** — the catch-all paragraph branch could consume zero lines, so
  `***bold***`, `# `, and `----` left the loop spinning. It now always consumes a
  line. 10 regression inputs.
- **Regex freeze** — the event loop cannot be timed and input caps do not bound
  backtracking, so the only real bound is a killable thread.
- **QR level L** — an independent decoder rejected our L output at every mask
  while accepting M, and the cause was never identified. L is removed rather than
  shipped as a code nobody can scan. M holds up to 106 bytes.
- **JWT persistence** — the token was written to the URL and to localStorage; a
  credential in a query string reaches browser history, server logs, and any
  Referer header. Both removed, with an e2e guard.
- **cURL Basic auth** — `btoa` throws above U+00FF, so any non-Latin-1 password
  failed the conversion. Now UTF-8.
- **Image decode** — a 10 MB cap never bounded decoded memory. 40 MP ceiling
  checked after decode, before any canvas is allocated.
- **PWA glob** — `**/ToolComponent.*.js` matched nothing while reading as if it
  worked. Deleted; the comment now records the measured evidence.
- **NUL placeholder** — could collide with the internal sentinel.
- **Date helper** — an out-of-range timestamp threw out of the `Result` contract.

## Retracted claims

1. "The format-information bit order is reversed." It is not. ISO/IEC 18004
   numbers format position 0 as the least significant bit; the reader was
   mirrored. The wrong fix survived one review because the round-trip reader shared
   the writer's assumption — a self-confirming test. The reader is now pinned to a
   literal format word and asserts the mirrored arrangement is rejected.
2. "Nuxt emits `ToolComponent-HASH.js`." It does not. The built CSS is
   `ToolComponent.HASH.css`, and no tool JS chunk carries a component name at all
   (`2uch8Usm.js`), so tool JS is not excludable by glob.
